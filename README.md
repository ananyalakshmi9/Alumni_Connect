## 💡 Overview

**Alumni Connect** is a robust, full-stack web application developed as a **Database Management Systems (DBMS) Mini-Project** (UE23CS351A). The primary objective was to design and build a deployable application that works seamlessly with a secure relational database. The platform facilitates professional guidance, networking, and engagement between PES University students and its alumni network.

## 🌟 Key Features & Functionality

The application supports two primary user roles (Student and Alumnus) and is built around the following features:

* **Secure Authentication:** Login system utilizing SHA2-256 hashing and user-role management (`tblUser_Login`).
* **Mentorship Management:** Students can request mentorship, and alumni can accept/manage the status of active mentorships.
* **Event Coordination (CRUD):** Alumni can create, edit, and delete events, while students can browse and register for upcoming events.
* **Job Posting Board (CRUD):** Alumni can post, edit, and delete job openings, providing students with career opportunities.
* **Secure Messaging:** Allows one-to-one communication between students and alumni through a dedicated Stored Procedure (`sp_SendMessage`).
* **Campus Insights Dashboard:** Visualizes data, including event attendance metrics (Max, Min, Avg) and top companies, generated by complex queries (see screenshot). [Image of the Campus Insights Dashboard showing Aggregate Query results]

## 🛠 Technical Achievements (DBMS Deliverables)

This project meets and exceeds the requirements for advanced database implementation:

### 1. Database Design & Normalization

* **Schema:** Defined using DDL commands, covering 10+ tables with extensive constraints (Foreign Keys, `UNIQUE`, `CHECK`).
* **Normalization:** The relational schema is structured in **Third Normal Form (3NF)**.

### 2. Advanced Routines

* **Stored Procedures:** Implemented for complex, transactional logic.
    * `sp_RegisterStudent`, `sp_RegisterAlumni`: Handles insertion into both profile and login tables.
    * `sp_SendMessage`: Manages message insertion, dynamically routing sender and recipient IDs.
* **Stored Functions:** Implemented for calculative logic.
    * `fn_GetAlumniEngagementScore`: Calculates a score based on job posts, events, and active mentorships.
* **Triggers:** Six triggers enforce critical business rules.
    * `trg_ValidateMentorshipDept`: Blocks cross-department mentorships.
    * `trg_PreventLateRegistration`: Prevents registration for events that have already passed.
    * `trg_update_login_email`: Syncs email changes between profile and login tables.

### 3. Complex Queries

All complex queries are embedded in the Python application or demonstrated in the SQL file:

* **Nested Queries:** Used to identify "Popular Events" where attendance is above the average across all events.
* **Join Queries:** Used extensively in data retrieval (e.g., fetching alumni list with department names).
